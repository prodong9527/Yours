# “她”V1 跨平台便携桌面版设计

状态：已完成逐节讨论并获用户确认

日期：2026-07-29

范围：个人自用；优先在 macOS 上开发和使用，同时支持迁移到 Windows

关联产品设计：[“她”第一版产品设计](2026-07-29-her-v1-design.md)

## 1. 目标

将“她”做成不依赖云端业务服务器、不要求预装开发环境的桌面应用。使用者复制完整的 `Yours` 目录后，可以在另一台电脑继续使用同一个人格、记忆、关系和成长状态。

本设计的成功标准是：

- macOS 和 Windows 使用同一套产品代码和同一种 Vault 数据格式；
- 每个平台提供自己的免安装可执行程序；
- 新电脑不需要安装 Node.js、数据库、Docker、Nginx 或本地服务；
- App、Vault 和模型配置可以放在任意有读写权限的位置；
- 关闭 App 后复制完整目录，在另一台电脑直接打开即可继续；
- 更换 App 版本或大模型不会让“她”失去连续性。

“复制即用”不表示同一个二进制文件可以跨系统运行。macOS 使用 `.app`，Windows 使用 `.exe` 和配套运行文件；两者读取同一个 Vault。

第一版发布目标限定为 Apple Silicon macOS 和 x64 Windows 10/11。未来需要 Intel Mac 或 ARM Windows 时，可以增加对应程序包，不需要改变 Vault。

## 2. 技术选择

采用：

```text
Electron
+ React
+ TypeScript
+ Node.js 本地核心
+ Markdown / JSON / JSONL 权威数据
+ 可重建 SQLite 搜索索引
+ OpenAI 兼容 HTTPS API
```

选择 Electron 的主要原因是它将 Chromium 和 Node.js 一起打包，适合“复制目录后直接运行”的目标。相较之下，Tauri 在 Windows 上依赖 WebView2；为了在任意目标电脑上免安装运行，需要额外携带固定运行时，削弱其体积优势并增加发布复杂度。

第一版接受 Electron 程序目录较大这一代价，优先保证运行环境完整、跨平台行为一致和本地文件能力稳定。

## 3. 系统边界

系统分为三层：

```text
界面层
聊天、记忆查看、人格编辑、设置、备份与恢复
        ↓
本地核心
对话编排、上下文组装、记忆提取、叙事更新、反刍、纠错
        ↓
便携目录
Vault 权威数据、模型配置、自动备份和可重建索引
```

### 3.1 界面层

界面只通过定义明确的本地接口访问文件、模型和领域服务，不直接读写 Vault。渲染进程不直接获得任意文件系统权限或模型 API Key。

### 3.2 本地核心

Electron 主进程承载本地核心，并负责：

- 定位和锁定便携目录；
- 按规则读写权威文件；
- 调用模型 API；
- 组装人格和记忆上下文；
- 执行反刍、纠错、备份和恢复；
- 维护可删除、可重建的索引。

所有长期状态由小型、边界清晰的服务管理。界面、存储、模型、记忆、叙事、反刍和备份之间通过类型化接口通信。

### 3.3 外部模型

第一版只要求模型服务兼容 OpenAI 风格的 Chat Completions 接口。远程地址必须使用 HTTPS；本机回环地址可以使用 HTTP。

模型不拥有权威记忆。更换模型地址、模型名称或 API Key 后，Vault 内容不变。

## 4. 便携目录

标准目录如下：

```text
Yours/
├── yours.manifest.json
├── 她-Mac.app
├── Windows/
│   ├── 她.exe
│   └── 运行环境文件/
├── config/
│   └── model.json
└── Vault/
    ├── persona/
    ├── conversations/
    ├── memories/
    ├── narratives/
    ├── corrections/
    ├── thoughts/
    ├── state/
    ├── attachments/
    ├── backups/
    └── .cache/
```

`yours.manifest.json` 标识便携目录及其格式版本。App 启动时从自身位置向上查找该文件；找不到时允许使用者选择已有目录或创建新目录。

所有长期数据路径都相对于便携目录保存，不写入 macOS 或 Windows 的绝对路径。文件名必须避开 Windows 保留名称和跨系统不兼容字符。

系统目录可以包含非关键缓存和崩溃信息，但它们不得成为人格、记忆、关系或恢复所必需的数据。删除系统缓存后，“她”仍应完整存在。

## 5. 模型配置与明文边界

第一版按用户决定，不加密 Vault 和 API Key，也不使用系统钥匙串。`config/model.json` 明文保存：

```json
{
  "schemaVersion": 1,
  "baseUrl": "https://example.invalid/v1",
  "model": "your-model-id",
  "apiKey": "replace-on-your-computer"
}
```

约束：

- 仓库只提供不含真实凭据的示例文件；
- 真实 `config/model.json`、Vault 和便携副本不得提交到 Git；
- API Key、Authorization 请求头、完整提示词和私人对话不得写入日志；
- 设置页明确说明目录被复制或丢失时，API Key 和私人数据会一并暴露；
- 后续可以新增可选加密，但第一版不为未来加密增加解锁流程。

普通自动备份只包含 Vault，不重复复制 API Key。手动生成的完整便携副本包含 Vault、模型配置、目录清单，以及便携目录中已经存在的各平台程序包。

## 6. Vault 权威数据

```text
Vault/
├── persona/
│   ├── constitution.md
│   ├── expression.md
│   ├── boundaries.md
│   ├── relationship.md
│   └── evolution.jsonl
├── conversations/
│   └── YYYY-MM.jsonl
├── memories/
│   ├── events.jsonl
│   ├── relationships.jsonl
│   └── understandings.jsonl
├── narratives/
│   └── <narrative-id>.md
├── corrections/
│   └── corrections.jsonl
├── thoughts/
│   └── thoughts.jsonl
├── state/
│   ├── current.json
│   ├── hanging-events.json
│   └── reflection-cursor.json
├── attachments/
├── backups/
└── .cache/
    └── index.sqlite
```

格式职责：

- Markdown：人格、表达方式、关系理解和叙事线等适合阅读与有限人工编辑的内容；
- JSONL：对话、记忆、纠错、念头和成长记录等只追加的历史；
- JSON：当前状态、游标、清单和配置；
- SQLite：全文搜索和关联检索的派生索引。

Markdown、JSON 和 JSONL 是权威数据。`index.sqlite` 可以随时删除并从权威数据重建，不得保存任何无法恢复的唯一信息。

对话文件按月分卷；如果单卷先达到 64 MB，则提前分卷。每条结构化记录至少包含稳定 UUID、`schemaVersion`、创建时间和来源 ID。

## 7. 人格与成长

人格分为三层。

### 7.1 固定层

- `constitution.md`：她是谁、基本价值取向和稳定人格；
- `boundaries.md`：她不会做什么，以及不操纵、不伤害和不冒充事实的边界。

模型不能直接修改固定层，只能由使用者在人格编辑界面手动保存。

### 7.2 可成长层

- `expression.md`：说话方式、称呼、节奏和习惯；
- `relationship.md`：她如何理解当前关系；
- `evolution.jsonl`：每次变化的前后内容、原因、来源和时间。

模型可以提出可成长层的候选变化。本地规则检查来源、幅度和边界后保存新版本，并保留演化记录。

### 7.3 即时状态层

- `current.json`：当前注意力和短期状态；
- `hanging-events.json`：仍在等待下文的重要事情；
- `thoughts.jsonl`：她想到但尚未表达的念头。

即时状态可以自然变化，但不能反向改写固定人格或原始经历。

## 8. 对话与上下文数据流

一次用户输入的流程：

```text
用户输入
  → 原话先追加到 conversations
  → 检索相关记忆、叙事和当前状态
  → 组装人格与当前心智上下文
  → 请求大模型
  → 回复追加到 conversations
  → 对话结束后执行一次反刍
  → 追加记忆、纠错、叙事变化或未说出的念头
  → 更新派生索引
```

每次模型上下文按以下顺序组装：

1. 不可自动改变的人格内核；
2. 表达方式和边界；
3. 她与使用者当前的关系；
4. 当前挂念和未完成事件；
5. 与本次输入最相关的少量记忆；
6. 最多 5 条活跃叙事线中的相关部分；
7. 当前对话。

检索遵循：

- 明确事实优先于推测；
- 已确认内容优先于未确认理解；
- 被纠正、封存或来源不明的内容不得作为当前事实；
- 生成内容必须引用原始消息 ID；
- 证据不足时表达不确定，不补全不存在的共同经历。

## 9. 反刍与主动表达

- 使用者结束对话，或最后一条消息后约 30 分钟没有新输入时，一次对话可进入反刍；
- 普通寒暄不触发反刍；
- 每次反刍最多形成 3 个候选念头；
- 下一次打开 App 时最多主动表达 1 个；
- 内容过期、证据不足、触及封存内容或时机不合适时保持沉默；
- 第一版不发送后台系统通知。

反刍、记忆提取或叙事更新失败时，保留原始对话和待处理游标，之后可以安全重试。

## 10. 一致性与异常恢复

### 10.1 写入

- JSONL 只追加，不就地重写历史；
- Markdown 和 JSON 先写同目录临时文件，刷新并校验后原子替换；
- 用户原话保存成功后才发送模型请求；
- 模型调用重试不得重复保存用户消息；
- 模型结构化输出校验失败时，仅放弃相应派生结果。

### 10.2 启动检查

启动时检查：

- 清单和目录格式版本；
- JSONL 文件尾是否存在未完成记录；
- Markdown 和 JSON 是否可解析；
- 派生索引是否匹配权威文件游标；
- 上次运行是否留下未完成写入或恢复事务。

只有 JSONL 最后一个不完整片段可以自动截断，并应先保存损坏副本。中间记录损坏或来源关系不一致时，不自动改写，改为只读模式并提示执行恢复。

### 10.3 单写者锁

- 一个 Vault 同时只允许一个 App 实例写入；
- 打开时创建包含进程和设备信息的锁文件；
- 已被使用时只允许只读打开或退出；
- 原进程已不存在时，可以清理陈旧锁；
- 第一版不支持从两台电脑同时编辑网络盘或同步盘中的同一 Vault。

## 11. 备份、迁移与升级

### 11.1 自动备份

- 每天首次发生权威数据变化后创建一次；
- 保留最近 7 个每日备份和 4 个每周备份；
- 自动备份只包含 Vault；
- 先写临时目录，生成文件清单和校验值，校验通过后再正式命名。

### 11.2 完整便携副本

由使用者手动生成，包含：

- Vault；
- `config/model.json`；
- `yours.manifest.json`；
- 便携目录中已经存在的 macOS 和 Windows 程序包；
- 文件清单和校验值。

完整便携副本输出为保持目录结构和程序权限的归档文件。生成界面必须提示该副本包含明文私人记录和 API Key。如果当前目录缺少目标平台程序包，生成仍可完成，但必须明确提示需要另行放入该平台程序。

### 11.3 恢复

恢复前先验证格式版本、文件清单和校验值，并为当前 Vault 创建恢复前备份。恢复失败时保留当前 Vault，不留下半恢复状态。

### 11.4 跨系统迁移

迁移步骤：

1. 关闭原电脑上的 App；
2. 复制整个 `Yours` 目录，或生成并复制完整便携副本；
3. 如果副本中尚无目标平台程序，再放入对应平台的程序文件；
4. 打开程序；
5. 自动完整性检查，必要时重建索引；
6. 继续原有对话。

路径、时间和换行读取必须在 macOS 与 Windows 间保持一致。写入统一使用 UTF-8 和 LF；读取兼容 CRLF。

### 11.5 程序升级

升级只替换对应平台程序：

```text
保留：Vault/、config/、yours.manifest.json
替换：她-Mac.app，或 Windows/ 下的程序与运行文件
```

如果新版本需要数据迁移，必须先创建完整自动备份，再通过带版本号、可测试的迁移器更新权威格式。App 版本回退遇到更高数据版本时，以只读模式打开，不擅自降级。

## 12. 第一版界面

### 12.1 初次打开

- 自动发现、选择或创建便携目录；
- 配置模型地址、模型名称和 API Key；
- 测试连接；
- 设置彼此称呼；
- 可选择交付最多 10 条记忆种子。

### 12.2 对话

- 默认主界面；
- 显示当前对话和最多一次主动浮现；
- 支持失败后的安全重试；
- 不显示复杂模型参数和记忆评分。

### 12.3 记忆与关系

- 查看事件、人物关系、理解和活跃叙事线；
- 从生成理解追溯到原始对话；
- 纠正、封存和解封；
- 手动编辑固定人格和边界。

### 12.4 设置与维护

- 修改模型配置并测试连接；
- 显示当前 Vault 路径；
- 生成完整便携副本；
- 恢复备份；
- 执行完整性检查和索引重建。

## 13. 测试

### 13.1 单元测试

- 目录发现和相对路径；
- JSONL 追加、分卷和尾部恢复；
- JSON/Markdown 原子替换；
- 单写者锁和陈旧锁处理；
- 人格层级和修改权限；
- 记忆来源、封存与纠错规则；
- 上下文组装和敏感字段过滤；
- 备份清单、校验和格式迁移。

### 13.2 集成与故障测试

- 用户消息落盘后模型断线；
- 模型超时、无效 JSON 和重复重试；
- 写入中断、JSONL 尾部损坏和索引丢失；
- App 异常退出后重新打开；
- 备份生成中断和恢复中断；
- 升级迁移失败后回滚。

### 13.3 跨平台验收

在 macOS 创建并使用 Vault，复制到 Windows 后继续对话，再复制回 macOS。确认：

- 原始对话逐条一致；
- 人物、记忆、叙事和纠错关系一致；
- 人格和当前关系状态连续；
- 索引能够在两个系统上重建；
- 没有绝对路径或换行差异导致的损坏。

## 14. 第一版完成标准

- 不安装开发环境，解压或复制程序后可以启动；
- 首次配置模型后可以稳定对话；
- 关闭和重启不丢失对话或内部状态；
- 模型或索引异常不损坏原始经历；
- 完整目录复制到另一系统后可以继续使用；
- 替换程序版本不会清空或暗中搬迁 Vault；
- 连续使用两到四周后人格、记忆和关系保持连续；
- 所有长期理解都可追溯到原始经历；
- API Key 只存在于明确可见的本地配置和使用者主动生成的完整便携副本；
- 不需要云端业务服务器、账号、同步服务或移动端。

## 15. 第一版明确不做

- Vault 或 API Key 加密；
- 多设备同时写入或自动同步；
- 云端业务后端、账号和登录；
- 手机访问；
- 自动更新服务；
- 应用商店发布；
- 后台系统通知；
- 语音、形象、外部 App 读取和代理行动。

这些能力只有在真实使用证明需要后，才进入后续独立设计。
